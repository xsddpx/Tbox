# 截图历史切换：Snipaste 机制研究与 Tbox 方案

日期：2026-11-12

## 1. 结论摘要

Snipaste 在**截图界面内**按 `,` 回到更早一张、按 `.` 切到更新一张。它的历史不是"一堆 PNG 文件"，而是**每次截图时的整屏原始帧加上当时的编辑记录**，所以翻到旧图后仍能重新调整选区、撤销/重做标注，而不只是查看。

Tbox 本轮实现的是**预览窗口内的左右切换**（UI-011），覆盖了"翻看历史"这个核心需求；Snipaste 的"可回退编辑"能力本轮未实现，差异见第 4 节。

## 2. Snipaste 的行为证据

| 证据 | 内容 |
| --- | --- |
| [官方内置快捷键 wiki](https://github.com/Snipaste/feedback/wiki/内置快捷键) | 截屏（Snip only）分组：`, (Comma)` 切换到上一次截屏记录，`. (Period)` 切换到下一次截屏记录。 |
| [用户 issue #1104](https://github.com/Snipaste/feedback/issues/1104) | 明确描述：历史记录"并不只是一张图片，而是截图范围内外的原始图像以及当初编辑的可撤销操作"；用 `,` `.` 翻到旧记录后可以"撤销某些编辑操作然后重新编辑"。 |
| [Snipaste 中文指南](https://www.snipasteup.com/163.html) | 先进入截图模式再按逗号/句号；数量由首选项"最大历史记录数"控制；基础版主要保存成功完成的截图，取消的不一定进入历史。 |
| [用户实践说明](https://www.bilibili.com/read/cv35671591/) | 翻选历史时"截图区域仍然保持，并且可以直接编辑"。 |
| [V2EX 讨论](https://global.v2ex.co/t/1148547) | 默认保存约 20 张全屏历史帧，可在设置中改为 0 关闭；说明历史以**整屏帧**为单位存储，内存占用可观。 |

### 2.1 还原出的实现要点

1. **整屏帧缓存**：每次进入截图模式时缓存整屏位图（默认约 20 张），而不是只存裁出来的结果。
2. **帧 + 编辑命令**：每张历史记录绑定当时的选区矩形和标注命令序列，因此能恢复到"可继续编辑"的状态。
3. **模态内切换**：`,` `.` 只在截图会话中生效；不在截图状态或正在输入文字时，按键回落为普通标点（指南 FAQ 专门解释了"为什么打出了标点"）。
4. **计数有上限**：数量由设置控制，超出后淘汰最旧的；基础版不保证记录被取消的截图。
5. **翻页不离开会话**：切换只替换画面内容，选区、工具条、模式都保持不变。

## 3. Tbox 的现有基础

| 能力 | 现状 |
| --- | --- |
| 截图结果缓存 | `CaptureCache` 已把每次完成的截图存为 `yyyy-MM-dd_HH-mm-ss[_NNN].png`，按写入时间倒序可枚举，自带 30 天 / 200 个 / 512 MB 清理。 |
| 主窗口"最近截图" | 显示最近 4 张，单击打开图片预览。 |
| 上次区域 | `CaptureHistory` 只记住最近一次选区矩形（对应 Snipaste 的 `R`），不含画面。 |
| 图片预览 | 原为单张查看，无历史概念。 |

结论：Tbox 已经有可靠的历史**结果**存储，缺的是**浏览入口**；不需要引入整屏帧缓存就能覆盖主要场景。

## 4. 本轮实现（UI-011）

在图片预览窗口内原地切换：

- 页头右侧：`‹ 上一张`、`当前 / 总数`、`下一张 ›`（标题与总数同行，读作"这是第几张"）。
- 键盘：`←` / `,` / 小键盘 `-` 切更早；`→` / `.` / 小键盘 `+` 切更新；`Home` 最早、`End` 最新。
- 鼠标：滚轮上 = 更早，下 = 更新。
- 首尾循环，连续按键不会卡在端点。
- 切换复用同一窗口；加载期间再次按键只保留最后一次目标（按修订号丢弃过期结果）。
- 只有一张截图时两个按钮禁用、不显示计数。
- 图片已被清理时保留当前画面，在底部状态栏说明"这张截图已被清理或移动。"。

### 4.1 与 Snipaste 的差异（有意为之）

| 维度 | Snipaste | Tbox 本轮 |
| --- | --- | --- |
| 触发位置 | 截图界面内 | 图片预览窗口内 |
| 存储内容 | 整屏原始帧 + 编辑命令 | 已完成的截图文件 |
| 翻到旧图后 | 可调整选区、撤销标注 | 只读查看，可复制/贴图/保存/识别 |
| 未完成的截图 | 基础版不一定记录 | 不记录（与缓存策略一致） |

如果后续要补齐"可回退编辑"，需要在 `CaptureSession` 中缓存整屏帧和 `AnnotationCommand` 序列，成本明显高于本轮，因此单独评估。

### 4.2 顺带修复

`LoadCachedAsync` 之前不设置 `Picture.CachePath`，导致：

- 预览无法知道自己对应缓存里的哪一张（历史定位失效）；
- 预览里点"复制/贴图/保存"会**再生成一份缓存副本**。

现已补上 `CachePath`，与主窗口缩略图贴图复用缓存文件的行为一致。

## 5. 实现中的两个坑（供后续参考）

1. **方向键被焦点导航吞掉**：在窗口上挂 `KeyDown`（冒泡）时，`←` 会先触发 Avalonia 的焦点导航、把事件改道去移动焦点，根本到不了窗口处理器；`→` 因为没有下一个可聚焦控件才侥幸冒泡上来。修法是在**隧道路由阶段**（`RoutingStrategies.Tunnel`）处理方向键并置 `Handled`。
2. **不要在 PowerShell 里改含中文的源文件**：`Get-Content`/`Set-Content` 往返会按本地代码页破坏 UTF-8 中文，造成大量字符串乱码。用编辑工具直接改。
