## 1. 文档职责

本文档是 Tbox 的产品行为、交互约束、验收标准和跨平台迁移语义的唯一活需求文档。它不记录易失的代码结构，也不替代发布记录：

- 本文档回答“产品应该做什么、怎样算完成”。
- `ui-design-system.md` 记录已确认视觉令牌、组件规格和原型映射；若与本文件的产品行为冲突，以本文件为准。
- `release-history.md` 记录“哪个安装包在何时生成、哈希是什么”。
- `project-handoff.md` 是历史时点快照；与本文档冲突时，以本文档和当前源码为准。
- 源码中的平台实现可以变化，但带编号的产品语义在迁移时必须保留。

需求状态使用：`已实现`、`部分实现`、`待实现`、`已撤销`。状态变更必须同时写入第 12 节变更记录。

## 2. 产品定位与范围

Tbox 是面向桌面端的模块化效率工具。当前 Windows 版本使用 .NET 8、WinUI 3、Windows App SDK 和 Win2D，目标平台为 Windows 11 x64。产品由“文件夹跳转”“截图与贴图”和常驻应用底座组成。

跨平台迁移时应优先保持用户可观察行为，快捷键、窗口 API、托盘 API、剪贴板 API、截图 API 和安装格式允许按目标平台替换。

## 4. 截图会话需求

| ID | 状态 | 需求与验收标准 |
| --- | --- | --- |
| CAP-001 | 已实现 | `F6` 开始截图；启动时冻结并按各显示器原始物理像素清晰显示画面，不得因逻辑尺寸自动解码而降采样变糊；鼠标所在显示器优先获得焦点。 |
| CAP-002 | 已实现 | 所有显示器属于同一个截图会话，用户可在任一显示器选择区域，但全局同一时刻最多存在一个选区。在另一显示器开始拖动时，旧选区及其未提交标注必须立即清除。 |
| CAP-003 | 已实现 | 选区松开后继续保留，不因点击工具栏、调整颜色/大小或选择工具而消失。 |
| CAP-004 | 已实现 | 截图会话一次只产生一张结果图；复制、保存、贴图或取消任一动作都会结束整个多显示器会话。 |
| CAP-005 | 已实现 | `Esc` 按层级取消当前文字/标注手势、工具或截图会话；指针取消事件不得误删已经完成的选区。 |
| CAP-006 | 已实现 | 鼠标中键在已有选区时直接创建贴图。 |
| CAP-007 | 已实现 | 最终输出只包含选区原图和已提交标注，不包含遮罩、边框、提示或工具栏。 |
| CAP-008 | 已实现 | `Ctrl+C`/`Enter` 复制并完成，`Ctrl+S` 另存为，`Ctrl+T` 固定为贴图。 |
| CAP-009 | 已实现 | 混合 DPI、负坐标显示器和逐屏像素捕获必须保持选区坐标正确。当前选区限制在开始拖动的单块显示器内；跨屏迁移时至少要保持全局唯一选区语义。 |
| CAP-010 | 已实现 | 截图开始后默认检测指针下的窗口并高亮其边界，单击采用检测区域，拖动仍可自由框选；`Tab` 在窗口检测与界面元素检测之间切换，必须在焦点导航处理前稳定响应。对检测生成且尚无标注的选区，切换模式时立即按指针位置刷新目标；手动或已有标注的选区保持不变并提示当前模式。无法取得界面元素边界时回退到窗口。检测不得把截图遮罩窗口自身当作目标。 |
| CAP-011 | 已实现 | `R` 将选区恢复为当前应用运行期间上一次成功完成截图时的桌面绝对区域；多显示器布局仍包含该区域时应自动切换到对应显示器，没有历史区域或区域已失效时给出非致命提示。 |
| CAP-012 | 已实现 | 选区创建完成后必须在四边中点和四角显示可拖动控制点；拖动边中点只调整对应边，拖动角点同时调整两个方向，指针形状应提示调整方向。拖动过程中边框必须连续跟手，不得因每帧像素取整或先保留自动检测框而乱跳；仅在松手时执行最终像素对齐。调整范围不得越出当前显示器或穿过对边，工具条在拖动期间暂时隐藏并在完成后跟随新选区；已有标注使用桌面绝对位置保留，缩小选区时仅裁掉范围外内容，不得清空标注。 |
| CAP-013 | 已实现 | 截图工具栏提供长截图入口；进入后退出冻结画面，显示黄色选区边框并立即捕获首帧，始终由用户在框内手动纵向滚动，不提供自动滚动或开始/停止动作。应用必须同时识别向上和向下的稳定滚动，允许在已捕获内容中反向移动并从任一端继续扩展；横向滚动暂不支持。选区右侧优先显示不写入结果的实时整图预览，绿色视口框随当前滚动位置和方向移动；右侧空间不足时预览可移到左侧。长截图控制条必须与截图工具栏共享深色容器、按钮尺寸、间距、Fluent 图标、前景色及悬停/按下反馈，只显示实时尺寸，以及贴图、保存、全屏预览、取消和复制动作；不得显示拖拽把手、纵横方向选择、状态说明、铅笔或剪刀式完成按钮。全部动作提供提示和可访问名称，控制条不得出现横纵滚动条或按钮裁切。应用在用户停止滚动后接受稳定帧并按垂直重叠区域拼接；只有画面多个纵向区域呈现一致位移时才可增加结果高度。光标移动、滚动条或悬停反馈等集中在少数纵向区域的变化必须视为重复帧，不得因变化面积较大而例外；资源管理器整行或文件卡片在光标经过时变色，既不得阻塞后续采集，也不得触发拼接增长。稀疏白底文字不得仅因全画面平均差异较小而误判为重复帧，匹配时应容忍选区顶部和底部的小范围固定内容。重复帧不增加高度，连续匹配失败可反向回退少量后继续或完成部分结果。达到 2500 万像素或 50000px 高度时自动完成。 |
| CAP-014 | 已实现 | 长截图结果以 PNG 进入可滚动预览，并支持文字识别、保存、复制和贴图。长截图和录屏都复用当前选区但不继承截图标注；已有标注时必须确认丢弃后才能切换模式。 |
| CAP-015 | 已实现 | 此处“边框”专指捕获选区边框，不指长截图实时预览窗口的外框。截屏、长截图和区域录屏必须共享截图选区的细线轮廓，以及四边中点、四角共八个白底彩边方形控制柄；仅颜色分别使用蓝色、黄色、红色区分模式。长截图和录屏不得因使用独立置顶覆盖层而出现系统白边、系统圆角或白色圆点，预览窗口外框保持中性且不承担模式区分。选区边框和控制柄只作状态提示，不得写入截图、长截图或录屏结果。 |

| ANN-012 | 已实现 | 截图和贴图均使用空格键显示或隐藏标注工具条；隐藏工具条不得把工具条写入最终图像，也不得丢失已提交标注。文字编辑期间空格仍由文本输入控件处理。 |

## 6. 文字识别需求

| ID | 状态 | 需求与验收标准 |
| --- | --- | --- |
| OCR-001 | 已实现 | 截图工具栏、贴图工具栏和贴图右键菜单均提供“文字识别”动作。截图触发后只结束一次当前多显示器截图会话；贴图触发后识别原始像素，原贴图的位置、显隐和标注状态保持不变。 |
| OCR-002 | 已实现 | 文字识别始终读取选区或贴图的原始像素，不包含箭头、文字、马赛克等 Tbox 标注。截图发起的原图仍遵循截图缓存策略，但不得保存识别文字历史。 |
| OCR-003 | 已实现 | 触发后立即显示默认 `800×600` 且可缩放的结果窗口；窗口限制在来源显示器工作区内，截图触发时默认不置顶，贴图工具栏或右键菜单触发时必须自动置顶并激活到最前，原图默认折叠。识别期间先保留原图并显示“识别中”。 |
| OCR-004 | 已实现 | 识别成功后显示可编辑、自动换行的文本和按 OCR 换行计算的逻辑行号，聚焦编辑器并全选结果；“复制全部”始终复制编辑器当前完整内容。用户可全选文本、展开原图及切换结果窗口置顶，原图展开后位于编辑区上方并占内容区约 35%。 |
| OCR-005 | 已实现 | 全局最多只显示一个文字识别结果窗口。再次触发识别必须复用并置前现有窗口，取消仍在运行的旧任务，以新原图和新结果替换当前内容；即使当前文字已编辑也不得创建第二个窗口。关闭结果窗口会取消仍在运行的识别并丢弃未复制文本。 |
| OCR-006 | 已实现 | Windows 版本使用系统离线文字识别能力并按用户首选语言创建识别器；图像任一边超过引擎上限时等比缩小，不放大小图。未安装可用识别语言、未通过已安装包运行、输入无效、未识别到文字或识别异常时，结果窗口保留原图并显示可操作的中文说明，不得关闭应用。 |
| OCR-007 | 已实现 | 首版不提供识别历史、搜索、翻译、自动复制、自动去换行、OCR 引擎/语言设置或原图与文字双向校对；内部识别结果仍保留行、词及原图位置数据，供后续图文联动扩展。 |

## 7. 区域录屏需求

| ID | 状态 | 需求与验收标准 |
| --- | --- | --- |
| REC-001 | 已实现 | 截图工具栏的录屏按钮只作为入口；点击后关闭截图遮罩并进入独立界面，不在录制过程中继续显示或使用标注工具栏。录制范围沿用当前单显示器选区，编码所需的偶数尺寸最多向内裁掉右侧或底部 1px。 |
| REC-002 | 已实现 | 录屏模式从等待开始即使用红色截图式边框，并显示 `00:00`、帧率选择、开始、系统声音和取消；帧率固定提供 5/10/15/25/60 FPS，默认 10 FPS，并且只能在开始前选择。录制状态继续使用红色边框并显示有效录制时长、停止和暂停/继续。边框和控制条不得出现在录制画面中。 |
| REC-003 | 已实现 | 录屏保持原始选区分辨率，按开始前选择的帧率生成 H.264 MP4，并始终包含鼠标指针。系统声音默认关闭且只能在开始前切换；启用时录制系统输出，不录制麦克风。系统声音不可用时降级为静音录制并明确提示。 |
| REC-004 | 已实现 | 暂停时不累计输出时长；停止后完成 MP4 母版并进入回放。回放提供播放/暂停、进度、当前/总时长、音量、格式选择、保存、重新录制和关闭，不提供裁剪、变速、录制后标注、视频贴图或摄像头。 |
| REC-005 | 已实现 | 每次新录制默认选择 MP4，不记忆上次格式。格式菜单固定提供“GIF - 图像，兼容性高，质量较低”“WEBP - 图像，质量好，兼容性适中”“MP4 - 视频，体积小，质量好”。 |
| REC-006 | 已实现 | MP4 直接复制母版且保留可用音频；GIF 为 12 FPS、最长边 1280、256 色循环图像；WebP 为 24 FPS、质量 80、最长边 1920 的循环动画。GIF/WebP 不放大小画面且不包含声音。 |
| REC-007 | 已实现 | GIF/WebP 转码先写应用临时目录，再复制到用户目标；转码可显示进度并支持取消。失败或取消必须删除目标半成品、保留母版和回放，允许重试或改存 MP4。 |
| REC-008 | 已实现 | 未保存关闭回放必须确认；保存、放弃或重新录制时必须先从回放界面卸载媒体、等待界面关闭完成，再释放播放器并删除当前临时目录，禁止因同步销毁媒体或先打开新录制界面导致应用退出。启动时清理超过 24 小时的崩溃残留。运行时依赖缺失或媒体功能不可用不得导致常驻进程退出。 |

## 8. 贴图需求

| ID | 状态 | 需求与验收标准 |
| --- | --- | --- |
| PIN-001 | 已实现 | 截图贴图保持原选区的屏幕位置和尺寸，并始终置顶显示。 |

| PIN-003 | 已实现 | `F8` 整体隐藏全部贴图，再次触发时在各自原位置恢复。 |

## 11. 跨平台迁移基线

迁移到 macOS、Linux 或其他桌面技术栈时，以下是不可丢失的行为契约：

1. 模块边界保持为“文件夹跳转”“截图与贴图”“应用底座”，平台适配通过接口替换。
2. 截图坐标统一使用虚拟桌面绝对位置与截图内部像素位置；必须覆盖负坐标、缩放和多显示器。
3. 多显示器截图是一个会话、一个活动选区、一个最终结果；不应为每块显示器暴露相互独立的可保存状态。
4. 标注模型应保持平台无关的命令序列，渲染层负责将命令转换为目标图形 API。
5. 序号的自动递增、默认大小 `22`、颜色/大小复用和撤销语义属于产品规则，不是 Windows 实现细节。
6. 贴图的原位置、置顶、锚点缩放、批量显隐、标注工具条和缓存保护属于产品规则。
7. 文字识别入口、只识别原始像素、可编辑结果、逻辑行号、智能窗口复用、取消及错误状态属于产品规则；识别引擎和语言发现机制可由目标平台替换。
8. 热键、托盘、剪贴板、窗口置顶、文件选择器和安装包签名由目标平台等价实现替换。
9. 迁移验收必须重新覆盖核心单测、屏幕捕获、坐标映射、标注最终渲染、文字识别、缓存和平台文件对话框集成。
10. 长截图的手动双向纵向滚动、右侧实时整图与视口预览、稳定帧识别、稀疏内容与固定边缘容错、双向重叠拼接、部分结果和尺寸上限属于产品规则；底层取帧方式可由平台替换。
11. 录屏的独立状态机、区域边框、5/10/15/25/60 FPS 选择与默认 10 FPS、暂停计时、三格式选择、默认 MP4、图像格式无声音、失败保留母版和安全关闭顺序属于产品规则；视频和图像编码器可由平台替换。

## 13. 后续自动维护流程

每次接到新要求时，在同一轮工作中执行以下动作；仅在用户明确要求“提交”时创建 Git 提交：

1. 判断是新增、修改还是撤销需求，分配或复用稳定 ID。
2. 在对应章节写清用户可观察行为、边界和可验证的完成条件。
3. 更新状态；若仅完成部分，不得标记“已实现”。
4. 在第 12 节追加日期、来源、原始要求摘要和受影响 ID。
5. 更新或新增自动化测试；平台交互无法完全自动化时，记录实际验证命令和证据。
6. 若行为影响 README、迁移语义或发布流程，同步更新对应内容。
7. 不在本文档记录密码、证书私钥、用户目录中的敏感内容或仅对一次调试有用的临时信息。

新平台开始迁移前，应先冻结本文档版本并逐条建立“原平台证据、目标平台实现、目标平台验收”映射；未映射条目不能视为迁移完成。
