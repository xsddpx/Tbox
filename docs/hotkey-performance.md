# 快捷键响应优化验证

## 本轮范围

1.1.40 优先优化截图、剪贴板贴图与截图完成动作，不以安装包大小为目标。普通截图立即发起采集，仅在长截图/录屏入口确实隐藏主窗口时保留 150 ms 等待，避免截入正在隐藏的窗口。

- Windows 快捷键少排队一次，共用处理使用输入优先级；快捷键录制和截图防重入规则不变。
- 屏幕像素与外部目标快照并行准备，目标枚举不占用界面线程；覆盖层创建前完成快照，避免识别自身。
- Windows 冻结画面直接使用 BGRA 像素；原 PNG 接口按需兼容。Mac 原生采集仍返回 PNG，本轮不宣称已消除该成本。
- 图片裁剪、标注合成、剪贴板图片和文字卡片不再为了内部中转立即编码 PNG。剪贴板仍独立持有图像，来源关闭后可继续读取。
- 贴图先显示独立像素副本，再后台编码、保存缓存并关联缓存路径；复制先提交剪贴板，再进行缓存保存和维护。隐藏的主窗口不因每次缓存写入解码缩略图。

未完成：增量笔画和马赛克缓存、长截图缩略预览、全部缓存维护和主窗口缩略图异步化。当前改动不能代替这些后续优化。

## 可重复验证

```powershell
dotnet test tests/Tbox.Core.Tests/Tbox.Core.Tests.csproj -c Release
dotnet test tests/Tbox.Desktop.Tests/Tbox.Desktop.Tests.csproj -c Release
$env:TBOX_CAPTURE_BENCHMARK = "$PWD\TEMP\capture-performance\comparison.json"
dotnet test tests/Tbox.Desktop.Tests/Tbox.Desktop.Tests.csproj -c Release --filter FullyQualifiedName~CapturePerformanceTests
Remove-Item Env:TBOX_CAPTURE_BENCHMARK
```

回归检查包括普通截图同步发起采集、主窗口原显示状态、录屏入口隐藏及取消恢复、直接像素裁剪和按需编码、独立副本生命周期、贴图在缓存完成前显示及之后关联缓存路径。

### 局部性能实验

Windows 本机 Release 测试，固定种子生成不含个人数据的随机不透明图像；每条路径先预热，再测 7 次。对比“原始位图 → PNG 编码 → 位图解码”与“直接创建像素位图”。两者不包含系统截图、窗口构建、合成器呈现、全局快捷键消息等待及磁盘操作。

| 尺寸 | PNG 往返中位耗时 | 直接像素中位耗时 |
| --- | --- | --- |
| 1920×1080 | 287.4 ms | 2.4 ms |
| 3840×2160 | 2137.9 ms | 16.7 ms |

这是难压缩的合成图像，不代表真实桌面内容，也不是快捷键总响应时间；只证明去除中转编解码能消除明显的处理成本。直接像素路径的统计托管分配不包含原始输入数组和原生位图内存，不表示图像不占内存。
