# 快捷键响应优化验证

## 本轮范围

1.1.41 优先优化截图、剪贴板贴图与截图完成动作，不以安装包大小为目标。普通截图立即发起采集，仅在长截图/录屏入口确实隐藏主窗口时保留 150 ms 等待，避免截入正在隐藏的窗口。1.1.40 的构建已中止，版本顺延避免复用可能已生成候选包的版本。

- Windows 快捷键少排队一次，共用处理使用高优先级异步派发，先于已排队的普通任务启动；快捷键录制和截图防重入规则不变。不能抢占已经运行中的界面任务。
- 屏幕像素与外部目标快照并行准备，目标枚举不占用界面线程；覆盖层创建前完成快照，避免识别自身。
- Windows 冻结画面直接使用 BGRA 像素；原 PNG 接口按需兼容。Mac 原生采集仍返回 PNG，本轮不宣称已消除该成本。
- 图片裁剪、标注合成、剪贴板图片和文字卡片不再为了内部中转立即编码 PNG。剪贴板仍独立持有图像，来源关闭后可继续读取。
- 贴图先显示独立像素副本，再后台编码、保存缓存并关联缓存路径；复制先提交剪贴板，再进行缓存保存和维护。隐藏的主窗口不因每次缓存写入解码缩略图。

未完成：增量笔画和马赛克缓存、长截图缩略预览、全部缓存维护和主窗口缩略图异步化。当前改动不能代替这些后续优化。

## 可重复验证

```powershell
dotnet test tests/Tbox.Core.Tests/Tbox.Core.Tests.csproj -c Release
dotnet test tests/Tbox.Desktop.Tests/Tbox.Desktop.Tests.csproj -c Release
$env:TBOX_CAPTURE_BENCHMARK = "$PWD\TEMP\capture-performance\comparison.json"
dotnet test tests/Tbox.Desktop.Tests/Tbox.Desktop.Tests.csproj -c Release --filter FullyQualifiedName~CapturePerformanceTests
Remove-Item Env:TBOX_CAPTURE_BENCHMARK
```

回归检查包括普通截图同步发起采集、主窗口原显示状态、录屏入口隐藏及取消恢复、直接像素裁剪和按需编码、独立副本生命周期、贴图在缓存完成前显示及之后关联缓存路径。

### 局部性能实验

Windows 本机 Release 测试，固定种子生成不含个人数据的随机不透明图像；每条路径先预热，再测 7 次。对比“原始位图 → PNG 编码 → 位图解码”与“直接创建像素位图”。两者不包含系统截图、窗口构建、合成器呈现、全局快捷键消息等待及磁盘操作。

| 尺寸 | PNG 往返中位耗时 | 直接像素中位耗时 |
| --- | --- | --- |
| 1920×1080 | 287.4 ms | 2.4 ms |
| 3840×2160 | 2137.9 ms | 16.7 ms |

这是难压缩的合成图像，不代表真实桌面内容，也不是快捷键总响应时间；只证明去除中转编解码能消除明显的处理成本。直接像素路径的统计托管分配不包含原始输入数组和原生位图内存，不表示图像不占内存。

## 安装与实际响应

1.1.41 已由[云端任务 42794116960](https://github.com/xsddpx/Tbox/actions/runs/42794116960)使用原持久证书签名。Windows/macOS 检查通过；云端 Windows 安装后实际截图、录屏及三格式导出通过。本机缺少 Windows 打包 SDK 和签名私钥，未更改证书或系统信任，下载同一签名产物后已从 1.1.39 覆盖安装至 1.1.41。本机安装检查确认系统 OCR、裁剪、共用界面及双显示器实际采集通过。Mac 实机安装和响应未验证。

本轮是性能试用，不发布新的公开正式版。安装包为 `artifacts/Tbox_1.1.41.0_win-x64.msix`，打包时间和 SHA-256 已记录于 `release-history.md`。

旧版 1.1.39 本机基线：向 Tbox 自己的消息窗口发送截图快捷键消息，等待全部显示器的截图窗口可见，再向 Tbox 发送取消。6 次为 1022.5、1091.5、993.8、1099.3、1008.4、1085.0 ms；排除第一轮后的中位数为 1085.0 ms。未保存屏幕图像，也未向其他应用发送输入。进程原本已运行，因此第一轮不能称为进程冷启动测试；此指标也不包含物理按键到系统消息的传递或显示器首帧绘制完成。

新版 1.1.41 在同一本机双显示器环境、使用相同消息探针测得 418.1、156.7、172.2、155.8、169.2、219.9 ms；这次探针新启动了进程，第一次截图为 418.1 ms，不能和旧版已运行进程的第一轮作严格冷启动对比。排除首轮后中位数为 169.2 ms，比旧版的 1085.0 ms 缩短约 84.4%。样本数较少，非受控桌面负载，不能当作 P95/P99 或所有机器上的承诺。

记录文件（Git 忽略）：`TEMP/capture-performance/hotkey-1.1.39.json`、`hotkey-1.1.41.json`、`measure-hotkey.ps1`，本机安装证据为 `TEMP/hotkey-1.1.41-installed/result.json`。新进程在复验后继续驻留，用户可直接尝试现有截图、贴图快捷键。

正常截图日志中的 `Capture ready` 记录入口到采集/快照准备完成、调用覆盖层显示完成的时间，不等于显示器首帧呈现时间。复验时分别观察冷启动第一次截图及连续截图，取消后再触发；保留多显示器、主窗口显隐和混合缩放覆盖。
